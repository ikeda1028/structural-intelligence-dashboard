# 行政価値ルーブリック v1（2026-09-27）

既存214資料の部分レビューを再分析する。新規の実態調査ではない。技術導入段階とは独立したTLAの分析枠組みで、自治体の公式格付け・公式目標ではない。7軸を別々に表示し、総合得点・順位・レベル差の自動計算を行わない。

## 7軸の到達条件（L1〜L4）

| id / 軸 | L1 個別負担軽減 | L2 一連のサービス改善 | L3 先回り・個別対応 | L4 地域の成果 |
| --- | --- | --- | --- | --- |
| burden / 住民の時間・手続負担 | 検索・記入・待ち時間の負担を減らす | 複数部署の手続を一度で済ませる | 必要手続の先行案内・再入力削減 | 制度を見直し不要な申請・来庁を減らす |
| inclusion / 公平性・利用しやすさ | 多言語・音声・操作支援で障壁を減らす | 対面・電話・オンラインいずれでも完了可能 | 利用を断念した人にも適切な支援が届く | 属性・地域による支援到達格差の縮小 |
| prevention / 個別支援・予防 | 必要な制度・相談先を探しやすくする | 福祉・教育等の支援をつなぐ | 本人の意向に沿い深刻化前に支援提案 | 支援継続により孤立・重症化・生活危機を減らす |
| quality / 判断の品質・説明責任 | 根拠を示した回答を提供 | 判断の不一致・確認漏れを減らす | 誤り・不利益の兆候を検知して人が点検 | 異議申立て・誤り分析を制度改善へ反映 |
| workforce / 職員の対応能力 | 記録・転記・検索負担を減らす | 部署間引継ぎ・二重入力を減らす | 繁忙・案件複雑さに応じた支援と人員配分 | 生まれた時間を相談・訪問等へ再配分し品質向上 |
| sustainability / 財政・公共資産の持続性 | 運用で費用・資産状態を把握 | 維持・更新・運営の選択肢を比較 | 故障・需要変化に予防的対応 | 将来負担と停止リスクを抑え必要サービス維持 |
| participation / 住民参加・政策学習 | 住民意見を収集・整理する | 意見への回答・採否理由を返す | 住民・企業と選択肢・影響を検討 | 成果に基づき施策・予算を継続・変更・中止 |

## 判定ルール

- 現在レベルは資料に裏付けられた業務・期間に限定。導入、ID付与、目標値、予算額だけで価値を達成したとしない。
- 根拠不足は current_level:null。0、低評価、未導入ではない。AIなしで達成した価値も評価できる。
- 利用案内は機能・提供の証拠であり、利用者の負担軽減の証拠と自動同一視しない。ただし根拠付き回答や意見受付など、レベル自体が提供状態を要件とする軸ではその範囲に限って判定可能。
- 試行内の結果も範囲を「実証」に限定すれば記録できる。本番や自治体全体へ外挿しない。推計・自己申告・市公表／測定法未確認・運用機能確認を区別する。
- 当該Lの必要条件を満たすか個別照合する。全体の平均、総合点、全庁達成とはしない。高いレベルがすべての事業に必要とは限らない。
- TLAの未来提案は仮説。自治体の公式目標とは分離し、公式目標は既存 non_financial_indicators の目標欄を参照。実現可能性・採択・費用対効果を保証しない。
- 未来提案は自治体ごとに1件、資料と関係のある特定業務を選び、原則2つの重点軸について目標レベルを提案。他軸の未来目標は未設定。全7軸に無理な目標を付けない。
- 実現条件、測定指標、企業・NPO等の役割、小さな検証単位、停止・見直し条件を具体化する。予算を未契約残額や市場規模と読み替えない。
- 個人情報、安全、公平性、本人の選択、人への引継ぎは必須条件。達成未確認であり、効率化の点数で相殺しない。支援受給・医療等の不利益判断をAI単独に任せる構想は作らない。

## 作業用JSON契約

各担当は code -> { current: {axis_id: {level:1..4, scope:string, basis:string, evidence_type:string, evidence:[{document_id,finding_index}]}}, future: {title:string, hypothesis:string, targets:[{axis_id,level:1..4,rationale:string}], evidence:[{document_id,finding_index}], conditions:[string], metrics:[{name,definition,method}], partners:[string], pilot:string, stop_rule:string} } を作る。

current は到達を裏付けられる軸のみ。未記入軸は統合時にnullとして「未確認」を明記する（未着手を達成へ置換しない）。evidence_typeは estimated / self_report / reported / operational のいずれか。全currentとfutureに本文レビュー済み文書内の有効なfinding参照が必要。未来仮説の引用は現状・課題・計画の根拠であり仮説の実現証明ではない。

metricsは2〜3項目。definitionに分母・対象工程・単位を、methodに基準期間・実証との比較・層別/品質確認等を記す。実測値や数値目標は作らない。conditions/partnersは各2〜3項目。自治体特有の資料・業務を踏まえ、汎用文のコピーだけで終わらせない。
