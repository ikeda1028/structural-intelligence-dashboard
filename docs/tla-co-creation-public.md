既存の画面、既存DBの内容、既存cronは変更していません。Next.jsとeslint-config-nextを15.5.26に更新し、再生成したpnpm-lock.yamlを同梱しました。新ページは独自HTML/CSSです。非公開の人脈・連絡先・内部調査履歴は読まず、公開組織をTLA会員やDAO参加者と認定しません。

## 収録範囲

国土地理院の名称コードデータを2026-09-26（日本時間）に取得し、行政区等を除外した1,741件、47都道府県のスナップショットを `lib/co-creation/registry.mjs` に保存しました。閲覧時の外部接続は不要です。これは現在の全自治体台帳との独立した完全突合を意味しません。元データの最終変更日として確認した日付は2024-01-09です。

詳細資料は三浦市・佐倉市・うるま市の9件。数値統計・全国の議事録分析は未取得。企業/NPOはフォーバル、ベネッセ、クボタ、ソフトバンク、フローレンス、TOPPANデジタルの6組織です。照合は13分野タグで、終了募集を除外し、既存連携は既存と表示します。自治体・政策の優劣や事業成立確率は生成しません。

共創の保存は利用者が押したときだけlocalStorageに保存します。サーバー・他の利用者には公開されません。ブラウザのデータを消すと失われるためJSON書出しを利用してください。

## 追加AI調査（既定では無効）

一般閲覧・収録企業の照合は追加キー不要。未収録企業のAI調査は `TLA_PUBLIC_RESEARCH_ENABLED=1` がない限り無効です。

管理者が有効化する手順:

1. 既存Supabaseで `supabase/migrations/20260926_tla_cocreation_quota.sql` を実行する。新規の制限テーブル/RPCだけを追加し、既存テーブルや既存RLSは変更しません。
2. Vercelのサーバー環境変数に既存の `OPENAI_SI_API_KEY` または `OPENAI_API_KEY`、`NEXT_PUBLIC_SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY` があることを管理画面で確認する。値をチャットに貼らないでください。
3. Previewで `TLA_PUBLIC_RESEARCH_ENABLED=1` を設定してテストする。モデル指定は `TLA_CO_CREATION_MODEL`（既定gpt-4.1-mini）。既存 `OPENAI_MODEL` は変えません。
4. プロバイダー側の費用上限・アラートを確認し、本番で有効化して再デプロイする。

UTC日付で全体30回、送信元3回に制限。DBのアドバイザリロックで複数インスタンスからの呼出しも原子的に計数します。失敗時も1枠を消費します。1回最大2検索ツール呼出し・2,000出力トークン。厳密な金額ベースの月額上限ではありません。ホスティング/DB等の費用は別です。

DB接続やRPCを確認できない場合は追加AIを呼びません。Origin確認はCSRF対策で、本人認証ではありません。認証・Bot対策・利用者別課金は別段階です。AIフラグ、DB migration、実AIの動作確認は公開コードの追加だけでは完了しません。

AI結果は実際の参照URL一覧と照合しますが、意味内容や法人同一性の完全な証明ではありません。結果の自動公開・DB蓄積はしません。利用者入力URLを直接クロールする公開プロキシはありません。

## プライバシー

追加調査でOpenAIへ送るのは企業名、任意の公式URL、調査指示です。`store:false` を指定しますが、提供者の全ログの不存在を意味しません。制限テーブルには日替わりHMAC識別子・日付・回数のみ保存。IPの平文や企業名は保存せず、7日超の制限データを次回利用時に削除します。通常のホスティングアクセスログは別です。

## 検証と運用

```bash
pnpm install --frozen-lockfile
pnpm test:co-creation
pnpm build
```

GitHub Actionsが単体テストとビルドを確認します。main反映時だけ、匿名HTTPによる本番ページ・データ・静的資産のsmokeテストも行います。これはAIプロバイダー/本番Supabaseへの有料・書込テストを含みません。公開完了は本番デプロイとsmoke結果を確認してください。

追加調査停止: `TLA_PUBLIC_RESEARCH_ENABLED=0` で再デプロイ。新ページ撤去: 今回追加したroute/lib/co-creation/public/co-creation-assetsを取り下げます。元のDB内容を巻き戻す必要はありません。表示資料は当事者の現在の参加意思を示すものではありません。
