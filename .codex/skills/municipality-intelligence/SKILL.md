# 自治体インテリジェンス収録スキル

自治体名または自治体コードを起点に、公開一次資料を収集し、数値・政策課題・制度変更・議会での論点を混同せず、公開レポートと共創OSのデータへ追加する。

## 基本原則

- 情報源は自治体、議会、総務省、各省庁などの公式一次資料を優先する。
- 「議員の質問」「行政の答弁」「計画への掲載」「予算計上」「公募中」「契約・選定済み」を別の状態として保存する。
- 予算額、補正額、決算額、執行額、契約額を混同しない。年度、単位、対象範囲、出典URLを必ず付ける。
- 条例は制度の根拠であり、条例本文だけから予算額を推定しない。関連する当初予算、補正予算、債務負担行為、契約議案へリンクする。
- 欠測、秘匿、未調査は0や「該当なし」に置換しない。
- 議会資料は、発言者・発言内容・行政の回答・議決結果・その後の予算/実施状況を可能な範囲で結び付ける。
- 企業とのマッチングは関連分野の候補提示であり、事業成立、採択、契約を保証する評価ではない。

## 収録する情報層

1. **基礎台帳**: 都道府県、市区町村名、自治体コード、区域基準日。
2. **全国統計**: 人口、世帯、産業、財政、教育、生活環境等。各指標に年度、単位、原表、状態を付ける。
3. **予算・公会計**: 歳入の款別、歳出の目的別・性質別、水道・下水道会計、道路・橋梁・公園等の事業費、住民1人当たり・世帯当たりの換算値。
4. **事業資料**: 計画、予算説明、決算、事務事業評価、公共施設・インフラ計画、公募・調達、既存協定、実証、運営者。
5. **議会**: 会議録、議案、議決結果、請願・陳情、意見書・決議。議論の論点と結果を別フィールドにする。
6. **条例・規則**: 公布日、条例名、改正内容、所管課、施行日、関連予算・事業への参照。
7. **DX・AI参入可能性**: 既存業務の負荷、データの所在、定型性、住民接点、調達入口、個人情報・説明責任を確認し、技術導入の仮説を作る。

## 予算データのルール

金額は原資料の単位を保持し、表示時に円・千円・億円を変換する。例:

- `budget_type`: `initial` / `supplement` / `settlement` / `contract`
- `fiscal_year`: 対象年度
- `category`: 款・項・目・事業
- `amount`: 原資料の値
- `unit`: 円、千円等
- `amount_state`: `value` / `missing` / `suppressed` / `derived`
- `source_url`: 公式資料
- `source_page`: PDFページ等

住民1人当たりや1世帯当たりは、同じ対象年度・対象区域の分母が確認できる場合だけ計算する。児童1人当たり、水道1家庭当たり、道路1平方メートル当たりなどは、分母の定義と対象範囲を明示し、分母がない場合は算出しない。

## 議会・条例の確認手順

自治体議会の「議案等の議決結果」「会議録」「請願・陳情」「意見書・決議」と、自治体の電子掲示場・条例ページを確認する。新しい資料が複数ある場合は、次の優先順で収録する。

1. 最新の定例会・臨時会の議決結果
2. 最新の補正予算と当初予算
3. 公布された条例・改正条例・規則
4. 会議録本文の一般質問、質疑、答弁
5. 議会の意見書・決議、請願・陳情

議会の記録は、次の形で要約する。

`topic` / `speaker_or_body` / `question_or_proposal` / `administrative_response` / `decision_status` / `related_budget` / `source_url` / `source_page`

## DX・AI参入可能性の調査

予算事業ごとに、単に「AIを導入できそう」と書かず、次の順で調査する。

1. **業務の詰まり**: 窓口待ち、審査、給付、相談記録、点検、台帳更新、議事録、問い合わせ、予測・配車など、時間・人員・再入力が発生する工程を特定する。
2. **データの所在**: PDF、紙、Excel、GIS、基幹システム、オープンデータ、センサー等を確認し、データの更新頻度・欠損・権利関係を記録する。
3. **技術の適合**: OCR・文書検索、生成AI要約、問い合わせ支援、異常検知、需要予測、GIS分析、ワークフロー、RPA、センサー/IoT等から、業務に対応する候補を挙げる。
4. **導入入口**: 委託、公募型プロポーザル、実証実験、補助事業、指定管理、共同研究、既存契約の追加、職員向け内製支援のどれかを判定する。
5. **リスクと検証**: 個人情報、要配慮情報、誤判定、説明可能性、職員の最終判断、セキュリティ、費用対効果を確認し、小規模な検証単位を示す。

DX・AIの記録には、次の項目を使う。

`business_problem` / `current_process` / `data_source` / `data_quality` / `candidate_technology` / `expected_effect` / `entry_route` / `related_budget` / `privacy_risk` / `human_review` / `pilot_scope` / `参入可能性` / `source_url`

参入可能性は、次のいずれかで表示する。

- **A: 公募・委託入口あり** — 公募、調達、実証、補助制度が確認できる。
- **B: 予算化済みで提案余地あり** — 事業はあるが、仕様・契約状況を追加確認する。
- **C: 課題・データは確認できる** — 予算未計上。政策提案や実証の段階。
- **D: 技術適用の仮説のみ** — 根拠資料が不足しており、導入可能性を断定しない。
- **E: 既存契約・選定済み** — 新規参入ではなく、連携・次期更新を確認する。

## 自治体DX進捗の調査

DXの進捗は、導入実績の有無だけでなく、住民サービス、庁内業務、データ基盤、AI活用、予算と調達の5面で調べる。自治体公式サイト、DX推進計画、情報化計画、オンライン手続一覧、オープンデータ/API、生成AI利用方針、議会会議録、当初・補正予算、入札・契約・公募資料を一次資料として収集する。

次の事実を確認し、単なる「DX推進中」という自己記述と、実際の利用・成果を分ける。

- **住民接点**: オンライン申請手続数、利用件数・利用率、電子予約、キャッシュレス、窓口待ち時間、問い合わせ自己解決率。
- **庁内業務**: 電子決裁率、紙・二重入力の残存、RPAの業務数と削減時間、システム間連携、処理日数、人材不足。
- **データ基盤**: オープンデータ件数、API、GIS、更新頻度、共通ID、施設・道路・上下水道台帳のデジタル化、センサー/IoT。
- **AI活用**: 生成AI方針、利用範囲、文書検索・要約、議事録、チャットボット、需要予測、異常検知、実証から本番への移行、検証指標。
- **予算・調達**: 情報政策費、電算管理費、標準化・ガバメントクラウド費、AI/RPA費、デジタル人材費、保守・更新費、契約期間、公募予定。
- **包摂と安全**: 高齢者・障害者の利用格差、紙・電話の代替手段、個人情報、要配慮情報、セキュリティ、説明責任、人による最終判断。

DX成熟度は総合点で断定せず、分野別に0〜5段階で記録する。

- 0: 紙・電話中心、データ未整備
- 1: 個別システムを導入
- 2: オンライン申請・電子決裁等を開始
- 3: 部局内または複数業務でデータ連携
- 4: 全庁的なデータ連携・AI活用
- 5: 効果測定、改善、民間共創まで継続

DX進捗の記録には、次の項目を使う。

`dx_domain` / `dx_stage` / `online_procedure_count` / `online_usage_rate` / `electronic_decision_rate` / `open_data_count` / `api_status` / `ai_policy_status` / `ai_use_cases` / `rpa_use_cases` / `data_digitization_status` / `dx_budget` / `maintenance_budget` / `system_renewal_timing` / `private_proposal_system` / `procurement_route` / `digital_divide_risk` / `source_url` / `source_date`

DX調査の成果物は、自治体別に「確認済み事実」「未確認」「導入仮説」「民間の入口」を分ける。導入仮説だけを実績として扱わず、公開資料に利用件数・予算・契約・効果指標がない場合は、その不足自体を記録する。

## 公開レポートの作り方

- 自治体ごとに、概要、統計、予算、議会、条例、事業、公募、出典を分ける。
- 予算の大項目と主要事業を同じ表に混在させず、階層を示す。
- 「確認済み」「資料上の記載」「残差による算出」「未確認」をラベル表示する。
- 議論中の提案を確定事業として表示しない。
- 公式原資料へのリンクを必ず残し、レポート自体を静的HTML等で常時閲覧可能にする。
- 共創OSへ取り込むときは5桁自治体コードで結合し、既存の企業・NPO情報や非公開人脈情報を混入させない。

## 完了条件

- 原資料URLと対象年度・単位が全ての数値に付いている。
- 議会の発言、行政回答、議決結果、予算を区別している。
- 条例と予算の関係が「直接計上」「関連事業」「予算額未確認」のいずれかで明示されている。
- 公開レポート、機械可読データ、生成手順を更新し、ローカル検証後に指定された公開先へ反映する。
- 公開後、主要URLのHTTP応答と表示内容を確認する。
